## 1. RINGKASAN EKSEKUTIF & STATUS KESIAPAN

Secara umum, arsitektur inti BaskaDrive telah berjalan dengan baik: alur sewa, keuangan, laporan, akuntansi double-entry, serta rendering PDF telah terintegrasi. Namun, dari hasil audit mendalam terhadap kode sumber dan fungsionalitas, ditemukan sejumlah **defisit fitur, celah UX, inkonsistensi validasi, dan fungsi yang belum tuntas (stubs/placeholder)**.

### Ringkasan Statistik Temuan Audit:
- 🔴 **Prioritas Tinggi (Critical/High Deficit):** 8 Temuan (Fitur setengah jadi / berpotensi mengganggu operasional).
- 🟡 **Prioritas Sedang (Medium Deficit):** 14 Temuan (Celah validasi, inkonsistensi alur, atau integrasi data yang belum otomatis).
- 🟢 **Prioritas Rendah (Low / Nice-to-Have Enhancement):** 11 Temuan (Penyempurnaan visual, UX polish, dan optimasi query).

### Status Perbaikan (update 15 September 2026):
- ✅ **Selesai diperbaiki:** 42 dari 45 butir temuan.
- ⏳ **Sisa (belum dikerjakan):** integrasi upah sopir ke jurnal penggajian, payment gateway (QRIS/VA), dan pembayaran borongan multi-invoice.
- 🔁 Perbaikan mencakup: UI peta & kalender dashboard, laporan keuangan formal (Laba Rugi, Neraca, Arus Kas), service jurnal terpusat + tutup buku, email invoice riil, QR verifikasi kwitansi, backup DB dari UI, hash token 2FA, permission aksi sensitif, validasi odometer, anti double-submit, penjadwalan cron, dll.

### 2.2 MENU: MASTER DATA

#### 2.2.1 Data Merek & Model
- [X] **Kekurangan:** Belum ada unggah gambar/foto representatif untuk katalog model kendaraan.

- [X] **Perbaikan:** Sudah ditambahkan kolom `photo` pada `m_vehicle_model` + field unggah/pratinjau foto pada form create/edit model.

#### 2.2.2 Data Unit Mobil
- **Kekurangan:** 
  - [X] 1. Fitur cetak barcode (`/master/vehicle/{id}/barcode`) view-nya masih sangat sederhana dan belum standar label stiker (ukuran stiker thermo 50x30mm).

- **Perbaikan:** 
  - [X] 1. Sudah: layout print barcode thermal 50x30mm via `barcode-pdf` (Spatie PDF / Browsershot + fallback Dompdf).
  - [X] 2. Sudah: relasi `m_vehicle.location_id` + tabel `vehicle_location_histories` — riwayat mutasi cabang tercatat otomatis saat lokasi unit diubah (halaman History unit).

#### 2.2.3 Data Pelanggan
- **Kekurangan:** 
  - [X] 1. Fitur blacklist pelanggan bermasalah (pernah merusak mobil/kabur) belum ada kolom status `is_blacklisted` dan alasan blacklist.
  - [X] 2. Validasi NIK dan Nomor SIM belum memeriksa format panjang digit Indonesia (NIK 16 digit).
- **Perbaikan:** 
  - [X] 1. Sudah: kolom `is_blacklisted` + `blacklist_reason` di `m_customer`; wizard Langkah 1 & pencarian pelanggan menolak pelanggan ter-blacklist.
  - [X] 2. Sudah: validasi regex `^\d{16}$` untuk NIK pada form create/edit.

#### 2.2.4 Data Karyawan
- [X] **Kekurangan:** Data karyawan belum terhubung secara otomatis satu-ke-satu (`one-to-one`) dengan tabel akun login `users`.
- **Dampak:** Menambah karyawan baru tidak otomatis membuatkan akun login sistem, admin harus membuat akun manual di menu Setup User.
- [X] **Perbaikan:** Sudah: checklist "Buatkan Akun Login" + pilihan role pada form tambah karyawan; `EmployeeController` otomatis membuat baris `users` dan assign role.

#### 2.2.5 Data Sopir
- **Kekurangan:** 
  - [X] 1. Belum ada peringatan otomatis (warning badge) jika masa berlaku SIM sopir (`license_expiry`) sudah mendekati habis (< 30 hari).
  - [X] 2. Pembagian komisi/upah sopir per transaksi kini terakrual otomatis ke jurnal akuntansi (DriverCommissionService).
- **Perbaikan:** [X] Alert badge kedaluwarsa SIM (valid / warning < 30 hari / danger expired) sudah tampil di tabel master sopir. [X] Integrasi biaya/upah sopir ke akuntansi SELESAI — akrual otomatis saat pengembalian (22 Sep 2026), tanpa modul payroll penuh.

#### 2.2.6 Lokasi / Cabang
- [X] **Kekurangan:** Belum ada pencatatan jam operasional cabang (jam buka/tutup) dan koordinat GPS kantor cabang.
- [X] **Perbaikan:** Sudah: field `opening_hours`, `latitude`, `longitude` di tabel `m_location` + input pada form cabang (dipakai juga sebagai fallback koordinat peta armada).

#### 2.2.7 Bengkel Mitra
- [X] **Kekurangan:** Belum ada rating/catatan performa kualitas pengerjaan bengkel mitra.
- [X] **Perbaikan:** Sudah: kolom `rating` (tampilan bintang di tabel) + `specialization` pada form dan daftar bengkel.

#### 2.2.8 Tipe Maintenance
- [X] **Kekurangan:** Interval servis hanya berbasis KM dan bulan statis, belum ada sistem trigger otomatis (notifikasi) saat unit mobil mencapai batas kilometer tersebut.
- [X] **Perbaikan:** Sudah: command `php artisan fleet:check-maintenance` memeriksa odometer vs jadwal servis, otomatis membuat record overdue, **dan kini dijadwalkan harian (06:30)** via scheduler.

#### 2.2.9 Manajemen Promo
- [X] **Kekurangan:** Kupon promo belum bisa dibatasi per kategori mobil (misal: promo hanya berlaku untuk kategori Hatchback/MPV, tidak berlaku untuk Luxury Alphard).
- [X] **Perbaikan:** Sudah: kolom `applicable_categories` (JSON) + multi-select di form promo; enforcement `isPromoApplicable()` saat perhitungan & penyimpanan sewa.

#### 2.2.10 Chart of Account (COA)
- [X] **Kekurangan:** Akun induk (parent) saat ini masih bisa dipilih langsung pada transaksi jurnal manual, padahal secara standar akuntansi hanya sub-akun terminal yang boleh memiliki mutasi debit/kredit.
- [X] **Perbaikan:** Sudah: akun ber-`children` di-disable di dropdown jurnal manual DAN ditolak di validasi server.

## 4. AUDIT STANDAR UI/UX, KONSISTENSI & RESPONSIVITAS

1. [X] **Responsivitas Layar Ponsel (< 768px):**
   - Area `menuoption` di kanan atas header tabel di layar ponsel yang sangat sempit bisa berdesakan dengan judul halaman.
   - *Solusi:* Sudah: wrapper header sudah `flex-column` pada breakpoint `sm`, ditambah CSS khusus (`app-enhancements.css`) agar tombol `menuoption` membentang penuh (*full-width*) di layar < 768px.
2. [X] **Indikator Loading pada Tombol Action-Link:**
   - Tombol `action-link-icon-text` saat diklik belum memunculkan animasi spinner loading saat request AJAX sedang berjalan.
   - *Solusi:* Sudah: `app-enhancements.js` — ikon berubah menjadi spinner `ri-loader-4-line` selama request AJAX, dan container `.menuoption` menampilkan spinner "Memuat pilihan aksi..." saat tombol aksi dimuat.

## 5. AUDIT KEAMANAN, VALIDASI & INTEGRITAS TRANSAKSI

1. [X] **Proteksi Double-Submit pada Pembayaran & Pengembalian:**
   - Tombol simpan pengembalian mobil dan bayar denda belum menonaktifkan diri (*disabled*) seketika setelah diklik pertama kali. Jika pengguna mengklik cepat 2 kali (double click), berpotensi memicu duplikasi record pembayaran.

   - *Solusi:* Sudah: aturan backend `return_mileage >= mileage kendaraan saat berangkat` (`min:<odometer awal`) dengan pesan error informatif di form pengembalian.
